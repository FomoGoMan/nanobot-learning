📦项目概览

什么是 nanobot？

nanobot 是一个受 OpenClaw 启发的人工智能助手实现。它用约 15,000 行代码实现了 OpenClaw 95% 以上的功能，而 OpenClaw 本身是一个更复杂的项目。

💡 关键洞察：nanobot 的设计哲学是"小而美"——用最少的代码做最有用的事。每个模块都经过精心设计，只保留核心功能。

AgentLoop 是 nanobot 的"大脑"——负责处理消息、调用 LLM、执行工具、管理会话。以下是它的核心结构：

1. 入口：_process_message

# nanobot/agent/loop.py:355-458 async def _process_message(msg, session_key=None, on_progress=None): """ 处理单条入站消息并返回响应 这是 AgentLoop 的主入口点 """ # 1. 解析会话 key = session_key or msg.session_key session = self.sessions.get_or_create(key) # 2. 处理特殊命令 if msg.content.strip().lower() == "/new": session.clear() return OutboundMessage(content="新会话已创建") # 3. 记忆整合（防止上下文溢出） await self.memory_consolidator.maybe_consolidate_by_tokens(session) # 4. 构建消息 history = session.get_history(max_messages=0) messages = self.context.build_messages( history=history, current_message=msg.content, media=msg.media, channel=msg.channel, chat_id=msg.chat_id, ) # 5. 运行 Agent 循环 final_content, _, all_msgs = await self._run_agent_loop( messages, on_progress=on_progress or _bus_progress ) # 6. 保存会话 self._save_turn(session, all_msgs, 1 + len(history)) self.sessions.save(session) return OutboundMessage(channel=msg.channel, chat_id=msg.chat_id, content=final_content)

2. 核心循环：_run_agent_loop

# nanobot/agent/loop.py:182-253 async def _run_agent_loop(initial_messages, on_progress=None): """ 核心 Agent 循环 不断调用 LLM 直到：1) 获得最终回复 2) 达到最大迭代次数 """ messages = initial_messages iteration = 0 while iteration < self.max_iterations: iteration += 1 # 获取工具定义 tool_defs = self.tools.get_definitions() # 调用 LLM response = await self.provider.chat_with_retry( messages=messages, tools=tool_defs, model=self.model, ) # 如果 LLM 调用了工具 if response.has_tool_calls: # 显示思考过程 if on_progress: thought = self._strip_think(response.content) await on_progress(thought) # 添加助手消息（含工具调用） messages = self.context.add_assistant_message( messages, response.content, tool_call_dicts ) # 执行每个工具 for tool_call in response.tool_calls: logger.info("Tool call: {}({})", tool_call.name, args_str) result = await self.tools.execute(tool_call.name, tool_call.arguments) messages = self.context.add_tool_result(messages, tool_call.id, tool_call.name, result) else: # LLM 返回最终回复，循环结束 final_content = self._strip_think(response.content) break return final_content, tools_used, messages
⚠️ 为什么需要循环？ 因为 AI 无法一步完成复杂任务。通过 Tool Call，AI 可以：
  • 搜索网络获取信息
  • 读写文件
  • 执行代码
  • 然后基于结果继续推理

3. 工具执行：ToolRegistry.execute

# nanobot/agent/tools/registry.py:37-58 async def execute(self, tool_name: str, arguments: dict) -> str: """ 执行工具的核心方法 1. 获取工具实例 2. 调用工具的 execute 方法 3. 返回结果（JSON 字符串） """ tool = self._tools.get(tool_name) if not tool: return json.dumps({ "error": f"Tool '{tool_name}' not found", "available_tools": list(self._tools.keys()) }) result = await tool.execute(**arguments) return json.dumps(result, ensure_ascii=False, indent=2)

LLMProvider 基类

# nanobot/providers/base.py class LLMProvider: """所有 LLM 提供商的基类""" async def chat(self, messages, tools=None, model=None, **kwargs): """ 发送聊天请求到 LLM :param messages: 消息列表 [{role: str, content: str}, ...] :param tools: 工具定义列表 :param model: 模型名称（可选） :return: LLMResponse """ raise NotImplementedError async def chat_with_retry(self, messages, tools=None, model=None, max_retries=3): """ 带重试的聊天请求 自动处理临时性错误（限流、服务器错误等） """ for attempt in range(max_retries): try: response = await self.chat(messages, tools, model, **kwargs) return response except self._is_transient_error(e): if attempt < max_retries - 1: await asyncio.sleep(2 ** attempt) # 指数退避 raise def get_default_model(self) -> str: return "gpt-4o"

工具系统是 Agent 的"四肢"——让 AI 能够执行代码、读写文件、搜索网络等操作。每个工具都是一个独立的 Python 类。

工具基类

# nanobot/agent/tools/base.py class BaseTool: """所有工具的基类""" name: str # 工具名称（用于注册） description: str # 工具描述（告诉 AI 何时使用） parameters: dict # 参数 schema（JSON Schema） async def execute(self, **kwargs) -> dict: """ 执行工具的核心方法 :param kwargs: 工具参数（来自 LLM 的工具调用） :return: 执行结果（会被发送回 LLM） """ raise NotImplementedError def get_definition(self) -> dict: """ 返回工具定义，用于告诉 LLM 工具的用法 """ return { "type": "function", "function": { "name": self.name, "description": self.description, "parameters": self.parameters, } }

💡 工具调用流程：
  1. AgentLoop 调用 LLM，传递工具定义
  2. LLM 判断需要调用工具，返回 tool_calls
  3. AgentLoop 执行工具，收集结果
  4. 将结果发回 LLM 继续推理
  5. 重复直到获得最终回复

🧠记忆系统 (Memory)

记忆系统让 Agent 能够"记住"之前的对话内容。它包含两个主要组件：MemoryStore（存储）和 MemoryConsolidator（整合）。

┌─────────────────────────────────────────────────────────────┐ │ 记忆系统架构 │ └─────────────────────────────────────────────────────────────┘ 用户消息 │ ▼ ┌───────────────────┐ ┌────────────────────────────┐ │ Session │ │ MemoryConsolidator │ │ (短期记忆) │ │ (记忆整合器) │ │ │ │ │ │ messages: [ │ │ • 检测上下文长度 │ │ {role, content} │─────▶│ • 压缩历史消息 │ │ {role, content} │ │ • 保存到长期记忆 │ │ ] │ │ • 清理冗余信息 │ └───────────────────┘ └────────────────────────────┘ │ ▼ ┌────────────────────────────┐ │ MemoryStore │ │ (长期记忆) │ │ │ │ • long_term/ │ │ • 语义压缩 │ │ • 关键信息提取 │ └────────────────────────────┘

MemoryStore

# nanobot/agent/memory.py class MemoryStore: """长期记忆存储和管理""" async def write_long_term(self, session_key: str, content: str): """写入长期记忆（归档）""" path = self.long_term_dir / f"{session_key}.json" await self._write_json(path, {"content": content, "timestamp": time.time()}) async def read_long_term(self, session_key: str) -> str | None: """读取长期记忆""" path = self.long_term_dir / f"{session_key}.json" if path.exists(): data = await self._read_json(path) return data.get("content") async def consolidate(self, messages: list[dict]) -> str: """ 将消息列表压缩为摘要 使用 LLM 进行语义压缩 """ prompt = f"Compress the following conversation into a summary:\n{messages}" response = await self.provider.chat([{"role": "user", "content": prompt}]) return response.content

MemoryConsolidator

# nanobot/agent/memory.py class MemoryConsolidator: """ 记忆整合器 - 检测上下文溢出并进行压缩 基于 token 数量而非消息数量 """ async def maybe_consolidate_by_tokens(self, session): """ 检查是否需要整合 当 token 数量超过 context_window_tokens * 0.75 时触发 """ estimated = self.estimate_session_prompt_tokens(session) if estimated > self.context_window_tokens * 0.75: await self._consolidate_session(session) def estimate_session_prompt_tokens(self, session) -> int: """估算会话的 token 数量（使用估算公式）""" # 简单估算：每 4 个字符 ≈ 1 token total_chars = sum(len(m.get("content", "")) for m in session.messages) return total_chars // 4
💡 为什么需要记忆整合？
  • LLM 有上下文窗口限制（通常 128K tokens）
  • 长期对话会超出限制，导致性能下降
  • 通过压缩历史，保持关键信息同时减少 token 消耗

💾会话管理 (Session)

Session 系统管理每个用户对话的上下文状态。每个会话都有独立的 ID 和历史消息。

# nanobot/session/manager.py class Session: """单个会话的数据结构""" key: str # 会话标识 (channel:chat_id) messages: list[dict] # 消息历史 last_consolidated: int # 最后整合的位置 def add_message(self, role: str, content: str): """添加消息到历史""" self.messages.append({"role": role, "content": content}) def get_history(self, max_messages: int = 0) -> list[dict]: """ 获取历史消息 :param max_messages: 0 = 所有消息, N = 最近 N 条 """ if max_messages == 0: return self.messages[self.last_consolidated:] return self.messages[-max_messages:] def clear(self): """清空消息但保留会话 ID""" self.messages = [] class SessionManager: """会话管理器 - 负责会话的创建、保存、加载""" def get_or_create(self, key: str) -> Session: """获取或创建会话""" if key in self._cache: return self._cache[key] return self._load(key) or Session(key=key) def save(self, session: Session): """保存会话到磁盘""" path = self._get_session_path(session.key) await self._write_json(path, { "key": session.key, "messages": session.messages, "last_consolidated": session.last_consolidated, })
